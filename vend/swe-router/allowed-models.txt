# Models this organisation permits, and that its coding agents can reach.
#
# NOTE ON NAMES: every model name in this file and in models.json is an
# indicative placeholder, not a model you can select -- closed-source models
# by tier and generation, open-weight models by parameter count and
# dense/MoE architecture. The measurements are real; the names are not.
# Replace them with the models you actually run, and see the README for
# benchmarking your own repository to get results under real names.
#
# One model per line. Blank lines and anything after a # are ignored, so
# annotate freely. Names are matched through model-aliases.json, so any
# spelling your assistant uses will work: open-dense-27b,
# open_dense_27b and Open dense 27B all resolve to the same model.
#
# This list is a hard constraint. A model missing from it is never
# recommended, whatever it scores. Delete this file and every model is
# permitted.
#
# It is also the whole candidate set. The skill takes every entry here as a
# model the developer can actually select, and does not go looking at the
# agent's model picker or provider config to second-guess that -- a model
# served through a proxy or driven by a second agent is invisible to such a
# check, and dropping it would silently cost the developer the cheaper
# option. So whoever maintains this file owns both halves of the promise:
#
#   list a model  ->  a developer can select it from the agent they run
#   cannot reach it  ->  it does not belong on the list
#
# Get that wrong in the generous direction and the skill recommends a model
# nobody can switch to. Get it wrong the other way -- leaving out something
# people do have -- and it silently recommends a pricier model instead.
#
# ---------------------------------------------------------------------------
# What ships here, and why you should change it
# ---------------------------------------------------------------------------
# These five are the models on the measured cost/quality frontier: nothing
# else scores at least as well for at most the cost, across the whole
# 21-task benchmark. That is a defensible starting point and a poor
# finished one, for three reasons.
#
# The first is the names: as above, they are placeholders. Nobody can select
# a model called open-dense-27b, so this file does not work until you have
# rewritten it against your own model list.
#
# One of the five, open-dense-27b, is also self-hosted, and the shipped file
# cannot know whether you serve it. If you do not, delete that line -- left
# in, it will be recommended, and a developer on a hosted API will be told to
# switch to a model they cannot select. The other four are hosted.
#
# Frontier membership also comes from whole-dataset means, which is not the
# ranking that decides a task. open-moe-2.8t-a104b is missing because
# closed-mid-gen6 beats it on average -- 79.49 to 79.17, at three fifths of
# the cost -- yet open-moe-2.8t-a104b scores higher on trivial work (81.80 to
# 77.36). And the two cheapest entries fall away on hard work: open-dense-27b
# drops to 71.45 and closed-efficient-gen6 to 60.00 on high-complexity tasks, and
# each failed one of the five.
#
# So add the models your developers can actually reach. If you self-host,
# these were on the frontier before the gen-6 runs and remain the best
# self-hosted value:
#
#   open-moe-2.8t-a104b  # 79.17, $4.33/task, self-hosted.
#   open-dense-31b       # 59.74, $0.87/task, self-hosted.
#   open-moe-35b-a3b     # 59.24, $0.26/task, self-hosted. Cheapest self-hosted.
